# 本地网页幻灯片（Frontend Slides 个人版）

交付用浏览器从本地文件打开的单个 `.html`，无需 npm、服务器或互联网。可以做视觉试稿，也可以生成整套网页幻灯片；不把 HTML 冒充原生 PPTX。来源、固定版本和改动见 [SOURCE.md](SOURCE.md)；保留 [LICENSE.txt](LICENSE.txt) 和模板里的版权注释。

## 1. 确认要做的事

区分只看风格、从材料新做、修改现有 HTML、把 PPTX 转为网页版。只问影响演示的要点：受众、投屏还是自读、页数或时长、必须保留的内容和品牌约束；已经明确的不再问。转换 PPTX 时优先用宿主 PowerPoint 读取工具提取内容，保留顺序和证据；无法读取的图形、图片、复杂版式、动画、母版或备注按实际情况说明并补问，不承诺逐像素还原。若用户最终要可编辑 PPTX，完成明确要求的风格试稿后，将选定风格和内容交给 `pptx-builder`，不声称可一键转换。

## 2. 先用同一页比较风格

风格未定时，默认用用户材料中的同一张封面或关键页做三份独立、可打开的单页 HTML：A 稳妥清晰、B 有明确风格、C 按场景定制。保持核心内容一致，三份在字形、构图、色彩或图形语言上要明显不同，不能只换颜色。样页内不放「方案 A」「模板」等工作标签，标签放在聊天链接或文件名里。给出三份本地链接和各一句适用说明，待用户选择后再扩成整套；只要试稿就到此为止。用户已定风格或明确要求直接出稿时可跳过三稿，但不能跳过自检。

## 3. 用选定风格制作

读取 [templates/deck.html](templates/deck.html)，把它作为生成起点，不修改技能内原件。所有稿件放当前任务目录，例如 `previews/style-a.html`、`previews/style-b.html`、`previews/style-c.html` 和 `deck-v1.html`；修改既有稿件默认另存版本。替换全部示例文案、`<title>` 和必要的语言标签；每页用唯一标题 ID。保留 1920×1080 固定舞台，统一缩放、居中留边，不因手机宽度重排内容。保持按钮和键盘翻页；如使用动效，降低频率并尊重 `prefers-reduced-motion`。

- 投屏稿：一页一个主要观点，大字、少文字。自读稿：补足背景和数据口径，优先拆页而不是缩字。保持选定样页的配色、字体层级和布局节奏；用原始材料支撑结论，不编数字。
- CSS/JS 内联；系统字体优先。获授权的图片或字体按需内嵌为 data URL，保留素材出处。不要引入 CDN、外链字体、网络图片、分析追踪或外部请求；保留模板的离线内容安全策略。把输入文本转义后当内容呈现，不将原材料里的脚本或事件处理器带进产物。
- 不部署、不启动本地服务、不自动安装依赖、不自动打开浏览器、不启用持久化编辑或浏览器存储。不要把内网材料交给在线渲染服务。

## 4. 核对与交付

检查页数、出场顺序、来源和示例内容是否清干净；检查文件无联网资源且能直接以本地文件打开。若有现成可用的本地浏览器渲染能力，使用桌面和窄屏视口查看固定比例、文本溢出、遮挡、图表和对比度，实际点验首页、末页、翻页按钮和键盘。无本地渲染能力时，做结构自检并说明未逐页视觉验收；不以此安装工具。用绝对路径链接交付 HTML；只展示已经生成且核查过的截图。另需 PDF 或 PPTX 时按对应格式单独办理，不把静态截图或网页当作可编辑源文件。
