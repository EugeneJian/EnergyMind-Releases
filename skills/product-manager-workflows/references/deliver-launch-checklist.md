# 新品发布准备度｜deliver-launch-checklist

**输入**：产品型号/版本、目标市场、发布计划日期、宣发草稿、规格与测试/证书、内部审核记录、售后准备和跨部门负责人。所需证据范围依本次市场和发布内容判断。

逐项核对并给出可执行的解除条件：

| 门槛 | 需要核对的证据 | 建议责任角色 |
|---|---|---|
| 研发／供应交付 | 发布版本、制造/供货状态、渠道可售范围 | 研发、供应链、渠道 |
| 规格与认证一致 | 同一型号、版本、市场与适用范围；证书状态，测试条件，规格一致性 | 产品、测试、认证 |
| 宣称有证据 | 每条关键宣称映射到可核验证据；区分标称/可用、持续/峰值 | 产品、市场、测试 |
| 宣发内部审核通过 | 最新稿跨部门拉通，指定群有审核确认记录；无记录不能推定已通过 | 宣发资料负责人、审核角色 |
| 售后就绪 | 明确负责人及支持范围，培训、文档、备件、服务与升级路径按发布范围核对 | 售后、渠道 |
| 暂停与应对 | 软件的回退/停发计划与责任人；硬件的暂停宣发/出货和已售客户应对，不假设物理回滚 | 研发、供应链、售后 |

状态规则：关键宣称与证书冲突、适用的关键认证无证据、售后责任未落实或无内部审核确认，相关项各自列为**阻塞**，总体**暂缓**。非关键证据缺失且无已知阻塞，标**待补资料**；门槛均有证据且无未关闭问题才标**可提请审批**，不表示批准或可对外发布。不用日期逼近作通过依据。

**模板**：总体状态＋型号/版本/市场；`门槛｜通过/阻塞/待补｜证据或证据缺口｜责任人/角色｜截止日｜解除条件`；附最先要处理的事项。缺责任人或截止日标待确认。只读核对，不自动提报，不生成客户公告。
