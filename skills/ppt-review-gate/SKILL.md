# PPT 汇报预审（PPT Director 方法参考）

目标是让受众看懂结论、知道依据，并能作出明确决定。本技能负责策划和预审；需要可编辑的本地 PowerPoint 时，交给 `pptx-builder` 制作，不另建导出流程。

## 1. 定受众与决定

先写一句：「面向谁，希望他们在会后同意、决定或采取什么行动？」同时记录已有材料、投屏或发阅、页数或时长，以及是否必须用公司母版。信息足够就直接推进；只问会改变叙事或版式的问题。未确认的假设标注为假设，不把用户没给的目标、数字或审批结论补成事实。

## 2. 写逐页导演稿

按听众的决策顺序排页，不必照搬原材料目录。通常先给核心结论或请求，再给证据、取舍与风险，最后写下一步。用下表交付，按需精简：

| 页码 | 结论式标题 | 证据或来源（含日期、口径或页码） | 表达方式 | 待确认项 |
|---|---|---|---|---|

每页只回答一个主要问题。趋势用趋势图，选项取舍用同口径对比，行动计划列责任人和时间；没有支撑数据，不编图。详细原始记录、长表和备查材料移入附录或演讲备注，别挤掉主线。质量复盘区分已验证根因、待验证假设、围堵和永久措施，不把措施完成写成效果已验证。

## 3. 预审并决定是否出稿

- **看逻辑**：只读标题能否串起论证？最后一页是否写明要谁决定什么，以及决定后的第一步？
- **查证据**：关键数字、因果或对比能否追溯？时间窗、单位、样本和基线口径是否一致？按「阻塞出稿 / 可带说明 / 版式优化」列问题，并写明需要补什么或如何改。
- **看关键页**：优先检查最影响决策的 1–3 页。默认给版式草图或结构说明；需要视觉确认时再做本地样页，查主次层级、字表密度和可能溢出的位置。不强制生成 HTML，也不默认联网、发布或上传材料。

如果用户只要预审，交付逐页导演稿、优先修订项和建议结论，止于此。用户要求先看或先确认时，在其确认后再出稿。若关键结论缺证据、数据冲突或强制母版缺失，指出阻塞项；可交付明确标记的草稿，但不要作为定稿。

## 4. 交接与验收

需要生成文件且没有阻塞项时，把受众、目标、逐页导演稿、已确认版式、来源和授权母版交给 `pptx-builder`。最终检查标题与证据是否一致、数据和单位是否还准确、文字是否溢出，以及要求可编辑的内容是否保留可编辑。只报告实际做过的验证，不把结构检查当作逐页视觉验收。
