# 路线图取舍｜roadmap-update

**输入**：带日期/版本和事项 ID 的路线图快照；变化请求及证据；硬截止与其来源；资源容量和跨团队依赖。没有快照，只能列候选新计划与待比较项，不声称已更新旧计划。

1. 标出现有承诺、事项顺序、可调整范围，说明变更为何现在需要决策。区分硬截止、预期窗口和未承诺目标。
2. 对比维持现状与变更方案。逐项写新增、提前、延后、缩范围或取消；对于新增事项列出挤占哪一项、哪支团队或哪个窗口。若容量影响未知，列需要验证的挤占候选，不默认加人或假设有余量。
3. 给出推荐选项、被放弃的选项及理由；资源不变时，考虑置换、缩范围或延期，并明确下游对认证、交付、销售或客户承诺的影响。若要量化排序，先确认评分口径与可核验输入，缺数据不硬填 RICE。
4. 产品经理（PrdM）提议范围和优先级；项目经理（PrjM）与相关团队确认容量、排期和依赖。方向未定用 Now / Next / Later；不把候选窗口写成对外承诺。

**模板**：`事项 ID｜原计划/快照｜建议计划｜变更理由/证据｜挤占项与影响｜前置依赖/责任角色｜决策与待确认`。结尾列“谁决策、依据什么、何时复核（未知则待确认）”。输出为变更草案，不写回飞书或跟踪工具。
